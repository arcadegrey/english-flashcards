# 学习页与词库并行准备（2026-10-28）

## 结果与范围

处理性能审查第 2 项：原先确认开始后等待词库、进入 learn 才触发 LearningView 的串行链路，现改为同一动作并行准备页面代码／CSS 与原有词库。全部成功且请求仍有效后，才一次采用词库并进入学习。没有静态引入学习页，也没有在首页启动、浏览目录或悬停时预取所有页面。

覆盖今日计划／计划设置的开始学习、其他页面调用相同动作的学习入口、四种测试模式，以及训练中心托福／雅思的全范围、Level／主题和单个 List。日常／四六级等原有即时分类入口、浏览器历史恢复仍使用同一个懒加载工厂；不额外改变其词库准备行为。

## 实现与兼容

- `src/utils/learningViewLoader.js`：共享懒加载工厂。首次调用才动态 import；并发准备与 React.lazy 复用同一个 Promise，成功后复用模块。失败清除请求缓存，下一次明确重试可重新请求。
- Vite 的预加载辅助函数会记住失败的 CSS URL。加载期间捕获失败的 stylesheet 链接，重试时先恢复这些链接，再继续 import，避免重试跳过 CSS 并进入无样式页面。监听仅存在于准备期间，完成／失败都会移除；重复失败继续留在原入口。沿用 Vite 生成的资源路径，不修改构建依赖或 PWA 策略。
- `useStudyNavigation` 和 `useVocabularyNavigation` 使用 Promise.all 同时开始词库与学习页准备，保留现有目录校验、合并、缓存与最多四路 List 准备。只有两者都成功才执行原有 commit 与导航。
- 计划／测试请求在 layout cleanup 随页面、模式、账号或计划分类变化失效；测试范围继续在选择动作中同步失效。较新的计划／测试动作使另一类旧动作失效，避免旧完成覆盖新的学习意图。范围入口继续保留上一批的视图／分类／Level／List／主题／账号代次检查。共享中的数据或页面请求不被强制 abort。
- 原有计划错误区和预览上的“重试”现在能重试此前失败的明确开始动作；若只是今日计划背景恢复失败，仍只重试原来的计划数据准备。测试和范围选择页沿用原有错误区、重试按钮与范围参数，没有新增 UI 模式。
- 学习页实际挂载、洗牌、稳定池、当前索引、认识／不认识、评分、草稿、历史、收藏、复习、账号隔离和同步格式均沿用现有实现。准备／进入本身不记录学习事件。全部 8699 条活动词与历史 ID 兼容，没有词条、音频、图片或数据内容变更。
