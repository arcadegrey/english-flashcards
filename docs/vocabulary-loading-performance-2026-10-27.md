# 词库首次加载减量（2026-10-27）

本轮继续处理完整词库等待较长的问题。此前的 24.561 秒是受控慢速下载验收时长，不是修复后所有用户都必需等待的时间；正式站点先前也观察到 25 秒未下载完的真实慢速传输。

## 加载路径

- 全部单词的今日计划：从已有 core 和用户记录中找出缺失的活动词条 ID，只请求这些词条所在的现有 TOEFL/IELTS List，并只将请求的词条加入页面。相同 List 去重，最多四路并发；词条跨多个 List 时选取体积较小的文件。
- 收藏页：只补齐未加载的收藏词，保留无法匹配的历史记录。
- 大量历史词涉及的 List 总体积超过增量文件时，自动使用增量整库，避免大量重复分片请求。
- 全范围学习、测试和指定类别计划仍获得完整活动词库；`core.json` 加 `extended.json` 合并为原来的 8699 条完整记录。已有 core 复用缓存，不再次下载到旧整库中。未下载完增量内容时，不提前启动不完整范围的全词库学习或测试。
- 旧版完整词库缓存可直接复用；新缓存仍使用原词库内容版本和公共数据命名空间，与账号/学习记录分离。
- 分类总数来自生成索引，不能因只补了少量历史词而少报词数；自定义词保留原有计数入口。过期、退役和未知 ID 不转移进度，也不重映射成活动词。

## 构建与维护

新增 `scripts/build-vocabulary-delivery.mjs`，由 `predev` / `prebuild` 自动生成：

- `src/data/vocabularyIndex.json`：3495 个 core ID、5204 个扩展 ID 对应的 91 个可复用 List 路径、文件大小和完整分类总数。
- `public/data/vocabulary/extended.json`：仅包含不在 core 中的 5204 个完整词条，无字段裁剪。

生成器校验 core、分片中的每一条数据与原始 `vocabulary.json` 完全一致，过期分片会阻止构建。更新词库仍先执行现有 `npm run words:split`，再构建。新文件需要随前端发布，不能只拷贝 JS。

增量文件由原始 full/core 推导，`vite.config.js` 不将它重复纳入内容版本哈希；原始词库和所有原有分片仍参与哈希，更新内容时照常失效，避免此次加载策略调整无端丢掉旧离线词库缓存。
