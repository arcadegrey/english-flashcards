## 本轮变更

2. **统一学习日**：`shared/studyDate.js` 固定使用北京时间（Asia/Shanghai），用于今日统计、计划词库计数、复习到期、连续学习、每周目标及老师周报。周报 SQL 使用北京时间周一零时对应的 UTC 时间查询；作业截止时间仍按设备输入的真实时间保存。页面在午夜、重新聚焦和恢复可见时更新今日状态。
3. **发布检查**：新增可复用 `.github/workflows/quality.yml`，PR 和手动执行检查；部署工作流须先通过测试、lint、跨时区回归、生产构建和 Worker dry-run，再运行现有部署步骤。部署使用 lockfile 安装的本地 Wrangler，与打包检查一致。这里没有执行 Git 推送或生产部署。
4. **多设备会话**：新登录保留其他有效会话；账号面板提供退出当前设备和退出全部设备。全部退出须验证登录、expected-user、同源请求和 JSON 格式，SQL 删除仅限当前账号；删除失败不显示成功。验证码使用原子条件更新，两个并发验证请求不能重复使用同一个验证码创建会话。旧设备重连时，带 `lastReviewed` 的较早复习计划不会覆盖较新计划。未带时间的旧记录保持既有兼容合并规则。
5. **加载性能**：页面按需加载；提示编译为 45 个按 ID 分组、带内容哈希的 JSON 文件，覆盖 8699 个活动词及 247 个历史词。每批约 200 条，打开词卡时加载当前批次，引用和例句高亮在编译时保留。账号弹窗拥有独立加载边界，等待资源期间仍可关闭并保持焦点管理。装饰素材源图与精灵图留在源码，不复制进产物。
6. **内容修复首批**：16 条词性、释义、语域或中文译文修复，逐条 before/after、来源及实际修改字段见 `data/vocabulary-quality-2026-10-25.json`。sales、states、works、online 的提示也对齐了基础例句。词头、英文例句、音标均不变，因此本批不用新增音频。

## 历史兼容与边界

- 没有 D1 schema 变更，不清空、转移或重编号用户记录，不重写已发布作业和已提交成绩快照。应一起发布 Worker 和前端，避免服务端词义与前端不一致。
- 旧日汇总只有日期，没有每次活动的时间戳；保留原日期，不能准确搬到北京时间。切换日期口径附近的历史日汇总与精确时间明细可能不完全一致。今后新活动按北京时间记录，历史周报明确提示旧日汇总保留原日期。
- 多设备同步继续沿用日汇总的最大计数合并，避免旧客户端重复上传导致虚增；这不是逐事件计数系统，不声称能精确相加两台离线设备同一天的所有独立活动。
- 学习提示与账号数据使用不同缓存。已打开批次在浏览器允许写入时显示“已保存，可离线查看（不含音频）”；未缓存批次首次离线时保留词条基础提示，并提供重试。缓存写入失败不会声称离线可用。首次打开并不代表所有词库、提示和音频已下载。
- PWA 继续预缓存应用代码及成品装饰资源；词库沿用原有版本缓存，提示在运行时单独保存。版本音频仍使用已发布 R2 对象，不进入前端包。

## 维护与发布

```bash

node scripts/apply-vocabulary-quality.mjs
node scripts/split-vocabulary.mjs

node scripts/report-vocabulary-followup.mjs
npm run hints:build
npm test
npm run lint
npm run build
npx --no-install wrangler deploy --dry-run
```

`prebuild` 自动重建服务端词库及提示批次；修改提示后应先生成批次再执行测试，避免检查过期产物。提交 `public/data/word-hints/` 和 `src/data/wordHintsManifest.json`，不提交 `dist`、音频 MP3、隔离验收脚本或测试账号。

上线顺序为既有工作流的质量检查、幂等 schema 步骤、Worker 与前端一起部署；本轮无额外数据库迁移。回退需同时回退前端与 Worker，不删除学习数据。真实生产账号验收仍需在发布后执行。
