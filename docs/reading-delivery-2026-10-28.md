# 阅读元数据与正文分层（2026-10-28）

首页、阅读目录和教师目录改用生成元数据；普通文章打开后才加载正文、译文和题目。原 26 篇文章、19 篇带题文章、69 道题和它们的 ID／顺序／答案均保持不变。历史、错题和班级作业继续使用原快照，不向最新文章自动替换。另补齐首次直接阅读时漏载的既有学习样式依赖，没有新增 CSS 规则或设计。

## 实现与兼容边界

- `src/data/readings.js`／`foundationReadings.js` 继续作为完整编辑源和 Worker 数据源；没有改写它们。`build-reading-delivery.mjs` 从相同来源生成元数据／去重小写英文词元，以及 26 份带内容 hash 的单篇 JSON。`predev`／`prebuild` 自动运行生成器，清理此生成目录中的过期文件；编辑或 CSV 导入后应重新生成或重启 `npm run dev`，生产构建会自动更新。
- 元数据保留标题、等级、来源、标签、考试类型、原计算方式的预计时长和题数。去重词元仍经过同一 `resolveVocabularyWord` 规则，并随当前已加载词库和认识记录重新计算，因此不把全库预计算统计代替实际可用词汇。全 core／全库／自定义词和认识变更的逐篇统计已与原实现比较。
- 普通阅读切页后，根层 `useReadingArticle` 与页面代码并行准备单篇内容。共享请求按文章 ID 去重，失败后可重试；用文章路径和尝试代次匹配结果、清理迟到响应，避免旧正文闪入新文章或离页后重新打开。加载和错误界面复用 AppLayout、现有卡片／按钮及共享加载动画。
- 完整内容到达前，不挂载原答题／历史 hooks，不展示答题或完成按钮，不创建临时草稿，不发送账号草稿／历史请求。完整后沿用原 `reading:ID`、`retry:ID`、`assignment:ID` 草稿键及完成／评分／同步逻辑。刷新仍按原导航规则回今日计划，重新进入文章后恢复草稿，没有改变刷新导航语义。
- `readingRetry.article` 和 `activeReadingAssignment.article` 没有延迟标志，直接使用原完整快照，包含历史 ID、原正文、只重做的题目和已提交锁定状态。账号变化仍按原页面 key 重挂答题 hooks；公共内容请求可共享，但草稿和历史不共享。
- 单篇响应验证内容版本、文章 ID／标题、正文、译文类型和题数。缓存使用独立 `flashcards-readings-<内容版本>` 命名空间；复用现有公共 JSON 加载器的去重、缓存读取超时和请求无进展超时，仅新增可选 cachePrefix 参数。原词库默认前缀及清理规则不变，双方不能相互清理缓存，也不触及用户进度、草稿或成绩存储。
- 单篇请求失败后，懒加载原完整文章模块作为后备。该模块仍被现有 PWA 代码预缓存策略覆盖，保留安装后未打开文章的离线阅读能力。新 JSON 不加入安装预缓存；普通成功路径只下载目标文章，不导入完整后备。代码／内容均未缓存的首次离线仍不保证可用。
- 教师文章选择和学生阅读记录只需要元数据，前端已替换这两处完整来源引用。发布仍只发送文章 ID，由原 Worker 固定完整文章／题目快照并评分；不调整 API、授权、截止时间或首次提交规则。

## 首次阅读样式修复

实际生产基线从首页直接进入阅读时，没有请求 `word-learning-refresh.css`，会出现大号未约束 SVG 和缺失卡片排版；以前先进入单词学习后才会间接拥有这份样式。原样基线与最初修改版都能复现。

`ReadingSessionView` 现在直接导入这份原有共享样式，再导入原阅读选项样式。没有修改 CSS 规则、页面布局组件或交互。首次阅读需要下载现有共享 CSS 的约 21274 gzip B，不能把这个修复的下载成本隐藏在正文分层收益中。CSS 按页面拆分仍留在下一批。

视觉对比采用原基线补加载其已有共享 CSS 后的正确排版，与最终自然加载样式的界面比较：320／390／768／1440px、浅深主题配对的正文、题目、计数和主要几何一致。原始缺样式截图和补齐后截图均保留，未把原样基线的错误排版当作设计目标。
