# 批量学习范围与词卡稳定性（2026-10-28）

## 结果与范围

处理性能审查的第一个问题：训练中心的托福/雅思范围在全部数据准备完整后才进入学习，准备期间不出现可答题的残缺词库。已开始的一组词卡固定顺序、数量和当前索引，后台补载不会再次洗牌。旧的学习记录、成绩、收藏、复习算法和账号同步协议保持兼容。

覆盖单个 List、托福 Level、雅思主题及各自全范围。失败留在原选择页并重试原范围；返回、换范围和账号身份变化使旧请求失效。成功准备不记录学习事件，只有实际点击学习动作才记录。

## 实现边界

- `src/utils/vocabularyPreparation.js`：按 manifest 解析目标 List，最多四路准备，逐 List 验证数组、数量和唯一 ID，全部成功后合并。保留同形词的不同 ID；雅思跨 List 重叠仍按 ID 去重，不拿目录成员总数冒充唯一词数。
- `src/hooks/app/useVocabularyCatalog.js`：继续使用原有目录/摘要/缓存 API，返回独立批次而不是每个 List 都修改全局词库。目录冷请求失败后可重新获取，并在请求仍有效时恢复目录状态。
- `src/hooks/app/useVocabularyNavigation.js`：持有准备状态和请求代次，一次采用准备结果、一次进入学习。范围/页面/账号变化在 layout cleanup 失效旧请求；失效后不继续排队新 List，正在共享的请求不被强制 abort。
- `src/hooks/app/useStudyNavigation.js`：以账号、模式和范围识别活动学习会话，在 layout effect 初始化词序，避免进入时先显示旧范围词卡。已启动的背单词会话不因全局词库增量而重排；离开后再进入、切换范围或显式重置时重新初始化。
- `src/components/app/AppPages.jsx`：背单词进度与数量消费活动池快照；考试模式继续消费原范围数据。四个词库选择视图接入同一准备状态与重试动作。
- `src/components/ToeflSelectionView.jsx` 与 `src/styles/vocabulary-selection.css`：沿用共享 chrome、ModuleCard、按钮和 LoadingState，只增加内容内的准备/失败反馈。准备时禁用开始和范围动作，返回与全局导航仍可用；重试按钮使用现有浅深主题 token。
- 冷进入雅思时显式引入原有 `word-learning-refresh.css`：雅思选择规则原来依赖访问学习页后才到达；留在选择页等待/重试必须先有原样式。没有重绘雅思页面，也没有实施审查中后续的 CSS 拆分。

目录预览本身不写学习状态。背景新增自定义词或目录内容会进入下次学习范围，当前会话继续原顺序。没有新增存储键、数据库字段、Worker API、词库条目、音频或图片。
