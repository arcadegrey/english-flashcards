# 老师、学生与班级

## 使用入口

- 新账号注册时选择“学生”或“老师”，可填写姓名 / 昵称。
- 已有账号点右上角 `Aa` 账号入口，选择“设置师生身份”。
- 设置后，同一入口显示“教学班级”或“我的班级”；手机可从“我的”进入。
- 身份和姓名保存在云端。有关联班级时不能切换身份，仍可修改姓名。

## 老师

1. 创建班级，获得随机生成的 10 位邀请码。
2. 把邀请码分享给学生。老师只能查看自己创建的班级。
3. 学生加入后，列表显示今日练词次数、已学习和已掌握词数、今日阅读篇数与答题数、最近同步时间。
4. 点击学生，在“单词学习 / 阅读练习”之间切换。单词页保留释义、学习状态、最近学习和下次复习时间；阅读页显示完成篇次、答题数、加权正确率、今日阅读，以及文章标题、级别、完成日期和答题成绩。
5. 可以按已学习、已掌握、错词、待复习筛选，或搜索单词 / 释义。学生记录为只读。
6. 更换邀请码会使旧码失效；现有成员不受影响。移除成员会撤销该班级对该学生的访问权限。

## 学生

1. 输入老师的邀请码加入班级，页面会先说明共享范围。
2. 加入后会尝试同步已有学习进度，也可点击“同步学习进度”。
3. 老师看到的是最近一次成功同步的云端记录；未同步的本机操作不在其中。
4. 退出班级会撤销老师访问权限，不删除自己的学习进度。

## 阅读记录口径

- 学生点击“完成阅读”后，文章与答题汇总写入 `studyHistory`，同步成功后老师可查看；尚未完成的答题不会出现在班级记录中。
- 同一文章同一天只记录一次，不同日期完成按不同篇次统计。阅读正确率为答对题数 / 已答题数，无答题记录时显示 `—`。
- 沿用已有保留规则，展示最近 90 个有记录的学习日。旧数据只有汇总或文章 ID 时保留统计，缺失的答题明细不会被当作零分。
- 前端与 Worker 共用 `shared/studyHistory.js`。冲突合并保留阅读文章 ID、逐篇结果、阅读与考试计数，按文章去重，重复同步不重复累加。
- 阅读题逐题选项未存入进度，本页展示文章级成绩，不展示未保存的逐题作答。
- 继续沿用已有 `study_history` JSON 字段及班级鉴权，阅读汇总沿用原有字段；作业和草稿需应用最新表结构，线上生效需部署前端与 Worker。

## 阅读作业

- 老师在所属班级中选择一篇带题阅读并设置未来的截止时间，发布后班级成员可在“今日计划”和“我的班级”中进入。
- 发布时保存文章与题目快照，避免后续词库/文章更新改变已发布任务。班级当前成员可见；退出或被移除后不能再读取或提交该作业。
- 学生完成全部题目后提交。服务端按快照计算成绩，不接受客户端传入的正确题数。首次提交保留成绩；网络重试不重复创建提交、不覆盖原成绩。
- 逾期可补交，老师端区分待完成、逾期、已提交和已补交，显示当前班级成员的成绩和提交时间。
- 草稿按账号、文章/作业分别保存到本机，登录后自动同步到 `reading_sessions`，不同作业与自主阅读互不混用；尚未提交的答案不向老师展示。
- 截止时间按操作者设备本地时间输入，以 UTC 存储，按查看者本地时间显示。
- 新增 `reading_assignments`、`assignment_submissions` 和 `reading_sessions` 表，通过现有部署步骤幂等创建。

## 数据与权限

新增独立表，不修改既有学习进度存储格式：

- `account_profiles`：账号角色、姓名、配置时间。
- `classes`：班级、所属老师、唯一邀请码。
- `class_memberships`：班级与学生的关联，联合主键防止重复加入。

所有接口通过原有 HttpOnly 会话 Cookie 鉴权。角色取自数据库，不能通过前端请求参数提升权限。
学生列表和进度详情同时检查老师身份、班级归属及成员关系。学生只能退出自己的班级。
老师不能修改学生进度，也看不到学生未学习的自定义词。查询返回 `Cache-Control: no-store`。

主要接口：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/classroom` | 当前身份和所属班级 |
| POST | `/api/classroom/profile` | 设置 / 修改自己的身份资料 |
| POST | `/api/classes` | 老师创建班级 |
| POST | `/api/classes/join` | 学生通过邀请码加入 |
| GET | `/api/classes/:id/students?page=1` | 所属老师查看分页学生列表 |
| GET | `/api/classes/:id/students/:studentId/progress` | 所属老师只读查看成员进度 |
| POST | `/api/classes/:id/invite-code` | 所属老师更换邀请码 |
| DELETE | `/api/classes/:id/students/:studentId` | 所属老师移除学生 |
| DELETE | `/api/classes/:id/membership` | 学生退出班级 |

新增作业接口：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET / POST | `/api/classes/:id/assignments` | 所属老师查看 / 发布阅读作业 |
| GET | `/api/assignments` | 学生查看所在班级的作业 |
| POST | `/api/assignments/:id/submit` | 学生提交答案，由服务端评分 |
| GET | `/api/assignments/:id/submissions` | 所属老师查看当前成员的提交情况 |
| GET / PUT | `/api/reading-sessions/:key` | 当前账号自己的自主阅读 / 作业草稿 |

## 部署与验证

上线前需部署新的 Worker 并应用 `worker/schema.sql`。现有 GitHub Actions 部署流程的
`npm run d1:migrate` 会执行该文件；建表语句可重复执行，不删除已有账号或学习数据。
本次开发不会自动修改生产数据库或触发部署。

`npm test` 包含角色、会话、跨班访问、成员撤销、邀请码更换、分页、旧账号兼容和学习状态测试。
后端集成测试使用 Node.js 22 的 `node:sqlite` 内存数据库运行真实 SQL，不请求线上账号或发送邮件。
原有词库加载、分类学习计划、学习算法与进度同步协议保持原有入口和用途。
