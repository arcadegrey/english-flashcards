# 启动依赖减量：第一批（2026-10-28）

## 结果与范围

继续性能审查第 3 项，完成三个独立使用边界：历史词全文随原有集合页加载；首次 Kokoro 静态播放才加载修正映射；首页庆祝在真实奖励触发后加载原有 GSAP 组件。布局、样式和学习操作保持原有组件。

已完成的学习页／词库并行准备继续保留。本批没有改词库／阅读索引分层、核心词库启动门控、图片调度、分类增量、CSS 拆分或同步协议，不将第 3 项整体标成完成。

## 历史词与计数

- `shared/retiredVocabularyIds.js` 仅保留 327 个历史 ID、同步判定和活动 ID 筛选。新增测试逐 ID 与完整归档比对，更新退役记录时必须同步更新此表；不能从拼写、分类或 ID 区间推断退役状态。
- `shared/retiredVocabulary.js` 保留 247 条原始归档和另 80 条归档的全部字段、顺序与原有导出；判定函数从轻量模块重导出。Worker、教师学生明细、旧考试评分、导入／审校脚本仍可以直接使用全文，不改其 API。
- `useStudyOverview` 的首页统计、错词数、计划排除与收藏匹配只使用 ID；不再将完整历史内容拉入入口静态依赖。根层 active vocabulary map 只投影当前目录，完整历史集合在页面边界解析。
- `AppPages` 将已学习／认识标记／错词／收藏的原始 ID 序列交给原有懒加载 `WordCollectionView`；其静态依赖包含完整历史词，模块准备好后才挂载交互。`resolveCollectionWords` 以稳定 ID 还原原顺序，当前／自定义内容仍覆盖同 ID 历史内容。没有边显示可答题残缺集合边补入历史卡片，也没有转移记录到替换词。
- 首页错词计数仍包括可解析的历史记录，收藏不会把已知历史 ID 错报为“无法匹配”。退役词仍不参与每日新词／复习和新作业。统计的 active／历史口径沿用原实现。

## 朗读与奖励

- `speech.js` 继续同步持有原 speech service、设置与 stopSpeak，只把五批修正映射的模块 import 放到首次静态播放。并发播放复用请求，成功后直接复用映射，失败后允许下次明确播放重试。
- `speechEngine.staticSpeech` 接受同步或异步修正 URL，等待后再次检查同一播放会话。停止、换词、切换 provider 或离页会立即结束旧调用，迟到映射不能播放音频或启动旧文本回退。
- 映射失败不盲目播放可能过期的基础 ID 音频，仍按原流程尝试当前文本的动态 TTS／浏览器回退。显式仅静态播放仍抛错；音色、速度、词／例句的版本 URL 和历史快照文本校验不变。纯浏览器 provider 不请求 Kokoro 映射。
- 首页 `StudyMomentum` 使用 `DeferredCelebration`，仅实际 trigger 才导入原 `CorrectAnswerCelebration`。奖励计算、通知、去重和原 seen key 持久化先按原逻辑执行，不等待装饰。加载失败不遮盖整页或撤销奖励，下个真实奖励可重试；卸载后不展示迟到动画。
- 原 GSAP 动画、12 个粒子、useGSAP 清理和减少动态效果处理不改。测试模式与学习页继续使用其原组件／GSAP 依赖，没有替换动画。首次动画下载慢时，通知先显示，装饰随后播放。
