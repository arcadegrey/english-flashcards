# 完整词库加载超时修复（2026-10-27）

后续减量加载方案及其真实缓存/限速前提见 `vocabulary-loading-performance-2026-10-27.md`。本文的 24.561 秒记录对应本轮较早的超时修复验收，不能当作后续版本必需的首次等待时长。

## 问题与定位

Safari 正式站点的今日计划显示“全范围词库加载失败：请求超时，请检查网络后重试”。今日计划为了恢复不在启动 core 中的历史词条，会加载完整词库。

- 本地 `/data/vocabulary.json` 返回 HTTP 200，约 3.3 MB，8699 条词汇。
- 正式站点同一路径返回 HTTP 200，但本机 `curl --compressed --max-time 25` 在收到 457092 字节压缩响应后仍未下载完毕。此观测说明慢速传输确实存在，不代表所有网络都有相同时延。
- 旧加载器把缓存读取、连接和完整响应体下载都放在一个 20 秒总时限中。即使下载持续前进也会被中止；缓存 open/match/json 卡住也会耗尽同一时限，阻止网络请求。

## 修复范围

- `src/data/vocabularyCache.js` 改为连接或响应体连续 20 秒没有进展才取消。每次收到非空响应块重置计时，响应头返回后重新计时；流式 UTF-8 解码保留跨块中文、音标等字符。
- 缓存读取最多等待 300 ms，之后走网络；异常、损坏、失去响应的缓存及后台写入不阻塞学习。正常缓存仍支持离线读取，内存缓存、同请求合并和内容版本隔离保留。
- 真正停滞的请求仍中止并释放重试入口；过期响应不能再写入内存或磁盘缓存。
- 不改词条、稳定 ID、学习记录、账号数据、同步协议或页面样式；不清除用户缓存来掩盖问题。

## 验证与发布

- 词库加载/合并专项 18 项通过；完整 `npm test` 218/218 通过。
- 新增持续慢速 UTF-8 流、缓存 open/match/json/delete 卡住、响应体停滞取消和重试、过期响应禁止落盘等回归。
- `npm run lint`、`npm run build`/PWA 通过。构建保留现有大 chunk 提示。
- 隔离 Chromium 真实页面同时模拟完整词库缓存 match 永不返回、HTTP 响应分 13 块持续 24 秒下载：24.561 秒后今日计划恢复，显示 8699 词和测试历史词的到期复习；没有超时提示。点击真实“开始学习”进入词卡，随后检查 390 px 手机界面，原学习记录不变、无未捕获页面错误。截图与临时脚本位于忽略目录 `output/playwright/vocabulary-timeout-*`，不进入发布产物。
- 原故障在 Safari 正式站点中确认；修复后慢速传输验收使用隔离本地 Chromium，没有宣称已经修好当前正式站点或完成 Safari 上线验收。
- 仅前端加载器变更，无 D1 迁移或 Worker 修改。发布前端构建后正式站点才能使用修复；本轮没有执行生产部署。
