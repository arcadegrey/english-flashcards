# 阅读逐句点读与旧实时语音移除（2026-10-29）

用户确认 Railway 已废弃，并选择“逐句点读”。现有许多文章只有一个自然段，按段播放仍会读完整篇，因此本轮按英语句子提供独立控制。

## 最终行为

- 每句句末增加原有音频按钮样式的真实播放按钮，保留原单词点词按钮。选中句子使用原蓝色语义高亮；等待语音开始复用共享加载动画。
- 一次只读选中的一句，同句再点停止，换句取消前一句，句子结束不自动续读。原“朗读全文”底部槽位改为“朗读首句／停止朗读”，不新增全局顶部控件。
- 状态区显示准备、朗读和可重试错误；正文、句序、字词高亮、题目、翻译及原阅读完成动作保持真实组件。
- 点词会停止句子并打开原弹窗。文章／账号／练习范围变更及离页取消所属朗读；迟到的 start、end、error 回调不能改写新句状态。单词发音仍可独立播放。
- 点读不标记认识、不答题、不完成阅读、不改变计划、成绩、草稿或同步。没有新增学习数据存储键。

## 语音来源

`speak(text)` 直接调用浏览器语音；`speakWord`／`speakExample` 继续优先播放当前音色的预生成录音，静态文件／映射失败时直接回退浏览器。删除前端实时合成的 fetch、音频 JSON／base64／blob 处理和 20 秒请求等待。

旧的 `VITE_KOKORO_TTS_URL` 和 `flashcards_kokoro_endpoint` 不再影响播放。`speech.js` 只读取静态单词／例句音频配置，正式构建不包含旧 Railway 地址或该环境变量键。本机忽略的 `.env` 中旧端点行已移除，其他配置保留；`.env.example` 和 Kokoro 文档同步更新。旧 endpoint 存取方法及工具常量保留兼容，不清除现有偏好数据。

预生成音色／语速继续控制单词和例句；普通文本仅使用原全局语速（包括模式菜单的慢速）及原浏览器英语声音选择。语音设置的说明明确这一区别。

浏览器语音列表为空时，仍最多等待原有 1 秒 voiceschanged。创建 utterance 后 5 秒未收到原生 start 时，结束本次等待并提供重试；已经 start 的句子不受该期限截断。该时间是程序阈值，不是系统声音下载／后台浏览器调度的时延保证。浏览器／操作系统声音可能自行联网，不能承诺所有声音均离线可用。

原本机 Kokoro 制作脚本和 R2 音频不删除，它们继续用于离线制作、发布录音，网站不依赖实时合成服务在线。

## 实现与兼容

- `buildReadingSentences` 是纯显示投影，优先用 Intl.Segmenter，缺失时使用标点回退，并保留基础缩写、小数、引号和段落换行。每段所有句子文本拼接等于原显示段落；不改写 canonical 正文或历史／作业快照。
- `createSentencePlayback` 是单个阅读视图私有的状态／取消协调器，React hook 通过 useSyncExternalStore 订阅。外部 AbortSignal 只取消所属语音；清理旧页面不能误停较新的单词／例句。
- 原共享语音服务继续保证最新操作优先、一次有效语速及旧音频映射取消安全；新增原生 start 回调、启动期限和所属取消信号。普通文本不受预生成录音语速重复叠加影响。
- 验证中发现上次样式边界漏分了阅读词弹窗复用的通用单词排版和发音按钮，按钮曾为 0×0。将这些通用规则从 word 模块移回全局 core，保留单词卡专属变体。295 个相关选择器／关键帧分支与 Git 基线的声明、媒体条件一致；恢复弹窗原有排版和 34px 控件，没有恢复全量样式导入。
