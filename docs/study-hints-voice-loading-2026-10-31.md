# 学习提示与语音等待修复（2026-10-31）

## 已确认的等待点

- 学习提示原先在点开提示后才开始下载，每组约 200 词／230 KB；CacheStorage 打开、读取和写入都位于显示内容之前，缓存停滞可以拖到原有 20 秒总超时。
- 首页语音设置通过 React.lazy 首次加载 JS/CSS。试听的静态录音没有启动／缓冲超时；音色切换只停止播放，没有同步复位试听按钮及旧请求的错误／完成回调。
- `stopSpeak` 原先每次都调用系统 `speechSynthesis.cancel()`，即使播放的是 MP3 或没有语音任务。此次只在确有本服务拥有的浏览器合成任务时调用。

本机公开只读探测：指定 `curl --noproxy '*'` 读取主站提示批次时发生约 5 秒 TLS 连接超时；同次音频域名 MP3 返回 200，约 1.42 秒。通过本机既有代理读取相同提示返回 200，235143 字节，约 9.17 秒。它们只是单次本机探测，不证明用户网络的固定根因、国内全线路可用性或本次修复已完成生产无代理验收。

## 交付行为

- 当前词进入卡片后准备提示，不等用户点开；仍只请求当前组，保留公共提示的同组去重、精确词头匹配、来源、历史词和缓存 key。
- CacheStorage 每次等待最多 250 ms。存储卡住时也显示已下载提示，未成功写入就不宣称可离线查看。稍后实际完成写入的结果可供后续读取使用。
- JSON 请求失败立即启用后备；超过 1 秒未完成时并行尝试后备。两条路径共享 12 秒交付上限，成功后取消未完成的 JSON 请求，失败允许重试。
- 构建插件直接由相同哈希 JSON 生成 `/assets/word-hints/<原哈希文件名>.js` 模块；没有复制提示源码、改写教学内容或依赖新的外部服务。开发服务器也支持该路径。浏览器原生模块导入失败后，显式重试使用新 query 避开失败导入记忆。
- 46 份后备模块按需加载，明确排除 PWA 安装预缓存；首页不下载整份提示库。取得后仍写回原有 JSON CacheStorage，旧离线副本继续使用。后备与主请求共用主站域名，主站全部路径均不可达时不能保证首次下载未缓存提示。
- 语音设置随应用代码加载，打开菜单不再额外等待该弹窗的 JS/CSS；仅映射代码与所选音色试听 MP3 在后台准备。单词卡同样仅预加载当前词录音。最多保留一个预加载 Audio，播放复用它，切换时释放旧预加载；预加载不自动播放。
- 音频映射准备、MP3 首次启动及后续缓冲各有 6 秒上限。已开始且正常播放的长例句不会被 6 秒截断。普通词卡保留浏览器语音回退；试听明确使用所选音色录音，失败显示可重试错误。听写仍只使用录音。
- 切换音色／语速立即取消旧试听、复位按钮并清除旧错误；请求序号保护新试听不被旧完成回调覆盖。关闭弹窗也停止试听。
