生产跨账号空学习列表写入测试被自动审批拒绝，原因是鉴权失效时可能损坏数据；没有执行该请求。采用生产只读隔离检查，并在一次性 SQLite 数据库验证跨账号写入拦截。

## 发现与修复

场景：设备 A 保留较旧的“标记认识”，设备 B 用较新的 `wordProgress.lastReviewed` 将同一词记为“不认识”。旧合并逻辑对 `masteredWords` 取并集，再删除相交的 learned/wrong 项；结果是复习计划已接受较新“不认识”记录，界面却仍显示“标记认识”。反向上传旧端也会重新引入旧认识状态。

通过两份独立生产登录会话复现：冲突标记为 true，较新的复习计划被采用，但词条仍留在 `masteredWords`。同样场景在真实 Worker＋隔离 SQLite 中稳定复现；修复前两项新回归用例失败。

新增共享 `mergeWordRecognition`，前端云恢复与 Worker 版本冲突合并共用：

- 两端认识状态矛盾时，采用较新复习时间对应的状态，使认识分类与已有复习计划规则一致。
- 没有有效复习时间或时间相同时，保留既有“标记认识优先”的兼容行为。
- 保留 ID 类型、去重顺序及无关词条；不更改学习范围、抽题、日计数的最大值合并、账号授权或 UI。
- 不增加协议字段、存储键或 D1 列，不迁移个人数据；未来正常发布需同时交付前端和 Worker。

该规则依赖现有客户端复习时间，不建立新的跨设备事件账本，也不声称解决设备时钟偏差、所有删除语义或多台离线设备日计数精确相加。
