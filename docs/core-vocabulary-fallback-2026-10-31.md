# 启动词库超时：完整核心词库后备（2026-10-31）

## 用户证据与未关闭的问题

用户在同一个联通 Wi-Fi 下用手机、Windows 直连，都长期停在“正在加载词库”或“词库加载失败”；同一手机切换联通流量约 10 秒能进入。记录为用户实测，未取得相应请求瀑布、DNS、IPv4／IPv6 或路由跟踪，不认定具体网络协议为根因。

此前 FlClash 的域名例外只恢复本机经代理访问；45 项功能验收和 6 次 HTTP 200 均经过代理，不能关闭国内直连 P1。已有交接现已补充这项最新边界。

当前实现的启动主请求是完整核心摘要 JSON（3545 条），核心未准备好时整站保留原加载／失败门禁。这次确认该请求没有随应用代码交付的后备；JSON 路径失败时即使 React 已加载也只能报错。修复的是这一恢复缺口，不声称解决所有国内宽带到 Cloudflare 的连接问题。

## 实现

- `scripts/build-vocabulary-delivery.mjs` 从既有 canonical core 生成 `src/data/coreVocabularyCatalog.json`，与公共核心摘要逐字段、顺序相同，不重新编辑词库或例句；同时生成核心 ID 范围，确保它与扩展词库区别校验。
- `src/data/coreVocabularyPreparation.js` 为 bootstrap 与 App 共用同一个请求。正常优先沿用原缓存／公共 JSON，不主动加载后备代码；主请求失败时立即尝试后备，或等待 2 秒尚未准备完成时按需尝试后备。
- 主路径和后备必须满足完整 3545 条、字符串化 ID 唯一、精确核心 ID 成员、词头及释义字段有效等校验。不会以空库或部分词库放行；不会强制启动下载全部 8749 词。
- 两条路径采用第一个校验通过的结果，并在本会话内共享。后备最多等待 15 秒；主路径保留原 20 秒无传输进展超时。两条都失败继续原错误／明确重试；后续重试可从恢复的主路径重新加载。
- 共用主请求不会因后备先完成而取消；原公共缓存可正常完成写入。迟到的主结果、导入错误或旧次重试不会替换已采用的词库或清空当前会话，不改变学习池排序／词汇身份。
- 后备仅惰性代码导入，由现有 PWA 规则预缓存；不新增缓存名称或清理规则，旧 core／full 缓存仍适用，完整旧 core 的例句字段不丢弃。
- 核心词库确认完整后，阅读独立目录、测试范围、按需例句等仍走既有流程。账号、同步、Worker、D1、音频、教师作业与个人记录结构不变。

## 成本与边界

当前产物后备为 `coreVocabularyCatalog-DRySLJGT.js`，708656 B，gzip 162629 B（约 159 KiB）。它未进入首页 HTML 的模块预加载清单，正常快速启动的独立浏览器没有请求它；但 Service Worker 安装仍会预缓存该代码。

PWA 从 104 项／2182.63 KiB 增至 105 项／2879.31 KiB 未压缩，新增大块提示如实保留。慢网络中主请求超过 2 秒时可能与后备重复传输核心摘要，这是恢复能力的代价，不声明总流量更少或所有首次加载更快。

如果应用 JS、后备 chunk 和主 JSON 在该宽带网络下都无法取得，仍不能保证进入；完全无缓存的离线首次访问仍不受支持。浏览器对失败动态导入可能保留失败状态，明确重试至少会重新尝试原 JSON 路径，页面刷新也可恢复；不承诺每种已失败模块都能不刷新重复下载。

国内真实直连验收必须在用户联通 Wi-Fi 无 VPN／代理环境完成，不能用本机代理浏览器、自动部署成功或故障注入替代。

## 发布与下一步

前端正常构建发布即可，现有 `prebuild` 已生成后备及精确核心 ID 范围；必须交付同一版 JS／metadata／公共目录。无需新增 Worker 逻辑、D1 迁移、音频生成或上传。既有 CI 仍运行幂等 D1 和 Worker／静态资源部署。
