# 自定义域名超时：定位、本机分流修复与线上复验（2026-10-31）

> 2026-10-31 用户直连补测（优先于下文代理验收结论）：联通宽带 Wi-Fi 下，手机与 Windows 均长时间加载仍无法进入；同一手机切换联通流量约 10 秒进入。两台设备连接同一 Wi-Fi。该结果由用户报告，尚未抓取对应 HAR／DNS／IPv4／IPv6 数据；不能认定具体协议或运营商出口为根因。国内直连可用性重新列为 **P1 未完成**。此前 45 项仅证明经过本机既有代理时的功能与离线恢复，不代表国内直连已经修复。

## 结论

此前自定义域名的加载阻塞已定位并在本机修复：当前 FlClash 本地配置中的 `DOMAIN-SUFFIX,cn,DIRECT` 将 `englishflashcards.cn` 强制直连，而该访问路径在本机出现 TLS 握手／首字节超时。Worker 的域名走另一条既有代理路径，因而形成同一部署两种入口表现不同的现象。

在当前本地配置的规则前部增加一条精确到本站域名后缀的例外，使用已经存在的“国外代理”策略：

```yaml
- DOMAIN-SUFFIX,englishflashcards.cn,国外代理
```

修复后，真实 `https://www.englishflashcards.cn/` 的阅读、句子听写及该 origin 的 PWA 离线恢复 **45 项浏览器断言全部通过**；重复请求首页、正文和词汇摘要共 **6 次全部 200**，总耗时约 **0.75–1.41 秒**，两个 JSON 与 canonical 数据一致。

这是**本机当前代理配置的分流修复**。没有改网站 DNS、Cloudflare 协议／证书、Worker、前端加载门禁、业务代码、学习数据格式或音频内容；没有将静态资源迁往另一个域名，也没有固定生产 IP。原来的失败记录保留为历史诊断证据，不再将其当作已确认的阅读业务缺陷。

## 原因与证据链

1. Cloudflare 只读 API 确认 zone active、未暂停；主域和 `www` 均启用并绑定 `english-flashcards` 的 production 环境。没有发现域名绑定错误。现有 OAuth 无权读取 DNS records 和 zone settings，这两项返回 403，未因此修改配置或申请更宽权限。
2. 正常域名请求有时可约 2.34 秒返回首页，但对 DNS 返回的两个 IPv4 地址分别访问首页、正文、摘要时，大部分请求在 TLS 握手前超时，另有请求完成握手后等不到首字节。IPv6 也有握手超时。TLS 1.3 专项探测被本机 curl 构建拒绝，未据此作协议故障结论。
3. 系统已有 HTTP／HTTPS／SOCKS 代理 `127.0.0.1:7890`。直接按域名使用这个代理请求正文和摘要，仍在约 8 秒握手超时，因此不是“填上代理地址”就能修复。
4. 仅用于诊断：保持原 URL、Host 和证书校验，经同一代理把连接目标指定为域名当时的 Cloudflare IPv4，正文约 2.89 秒返回 200。这个结果缩小到了按域名分流的差异；最终验收没有沿用此固定 IP 方式。
5. 对当前本地配置作字段级检查，确认规则尾部存在 `DOMAIN-SUFFIX,cn,DIRECT`，之后才是 `MATCH,国外代理`，没有本站例外。当前配置是本地文件，没有远程订阅 URL。添加本站例外并重新应用后，生成的核心配置中该规则排在通用 `.cn` 直连规则前。
6. 修复后正常域名 URL（无 `--resolve`／`--connect-to`）的正文请求约 0.80 秒返回 200；两轮首页／正文／摘要测量全部成功。正文和词汇摘要在验收页面中的带版本查询请求也实际返回 200。

这些证据支持本机分流路径是本次阻塞原因，不将它扩大为所有地区的公网直连质量结论。
